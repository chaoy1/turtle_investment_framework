# A 股官方证据优先分析系统设计

## 1. 目标

在不使用付费数据源的前提下，提高 Turtle Investment Framework 对 A 股公司的事实准确性、分析深度、可追溯性和结论置信度。

系统以公司和监管机构正式披露为财务事实主源，以免费公开行情为估值补充。Python 负责采集、标准化、计算和确定性校验；Agent 负责基于证据的商业判断、风险分析和估值假设选择。任何缺失、冲突或低质量数据都必须显式降低结论置信度，禁止用推测值填充。

## 2. 成功标准

一次完整 A 股分析应满足以下条件：

- 每个影响投资结论的核心财务数值均可追溯到正式披露文件、报告期和页码或结构化事实标识。
- 行情、市值等估值输入记录底层来源、交易日期和采集时间。
- 报告能够区分事实、Python 计算结果、Agent 判断和情景假设。
- 同一指标的来源、期间、单位或合并口径冲突能够被自动发现并阻止高置信度结论。
- 估值至少包含穿透回报率、历史估值区间以及适用的现金流或股利模型，并输出情景与敏感性而非单一精确目标价。
- 报告交付前通过证据完整性、数值一致性、分析完整性和估值可追溯性门禁。
- 数据不足时仍产出报告，但醒目标记限制、缺失项和低置信度，不形成伪精确建议。

## 3. 非目标

- 不接入付费行情、付费财务数据库或需要商业授权的数据服务。
- 不把财经门户转载、搜索摘要或模型常识当作正式披露的替代品。
- 不预测短期股价，不生成确定性的买卖承诺。
- 不在首期构建面向所有 A 股行业的完整专用模型；先建立通用框架和少量差异显著的行业适配器。
- 不用多个低等级来源的“多数一致”覆盖一个更高等级的正式来源。

## 4. 来源等级与裁决规则

### 4.1 来源等级

| 等级 | 来源 | 允许用途 |
|---|---|---|
| S | 巨潮资讯、上交所、深交所、证监会、上市公司正式公告 | 财务事实、公司行为、监管事项、治理事实 |
| A | 财政部、人民银行、国家统计局及行业主管部门 | 会计规则、利率、宏观和行业基准 |
| B | AKShare 可识别底层来源的免费行情 | 股价、成交、市值及历史估值补充 |
| C | Yahoo Finance 等免费备用源 | 主来源不可用时的降级行情，不覆盖正式披露 |

### 4.2 裁决顺序

冲突按以下顺序处理：

1. 正式更正或更新公告优先于原公告。
2. 审计后年报优先于业绩快报和未经审计数据。
3. 同等级来源中，报告期、合并范围、币种和指标定义完全匹配者优先。
4. 行情使用明确交易日的最新可用记录，不以抓取时间代替交易日期。
5. 无法裁决时保留全部候选值，标记 `unresolved`，相关指标和结论降级。

不得对冲突数值求平均。低等级来源不得覆盖高等级来源。

## 5. 证据模型

每项关键事实保存为 `EvidenceRecord`，字段如下：

| 字段 | 含义 |
|---|---|
| `security_code` | 规范化证券代码，如 `600887.SH` |
| `fact_name` | 稳定的指标名称 |
| `value` | 原始或标准化数值 |
| `unit` | 原始单位和标准单位 |
| `currency` | 币种 |
| `period_start` / `period_end` | 指标覆盖期间 |
| `as_of_date` | 时点指标日期 |
| `scope` | 合并、母公司或分部口径 |
| `source_tier` | S、A、B 或 C |
| `source_type` | 年报、季报、公告、监管文件或行情 |
| `source_title` | 文件或数据集标题 |
| `source_url` | 原始来源地址 |
| `local_artifact` | 本地原始文件路径 |
| `page` | PDF 页码；无页码时为空 |
| `published_at` | 正式披露日期 |
| `collected_at` | 采集时间 |
| `validation_status` | `verified`、`degraded`、`conflict` 或 `unresolved` |
| `validation_notes` | 口径、冲突和降级说明 |

一次分析生成 `evidence_manifest.json`。Markdown 数据包和最终报告只引用 manifest 中的稳定证据标识，不复制无法追溯的裸数值。

## 6. 组件设计

### 6.1 官方来源注册表

新增 `scripts/official_sources.py`，负责：

- 定义来源等级、允许的主机和允许用途。
- 根据证券代码路由到上交所、深交所或巨潮资讯的正式披露入口。
- 将来源名称、底层主机和等级标准化，避免 AKShare 等聚合层掩盖实际来源。
- 拒绝把未知主机标记为 S 级或 A 级。

### 6.2 公告定位与原件保存

新增 `scripts/filing_locator.py`，负责：

- 定位年报、半年报、季报、业绩更正、问询回复、处罚、回购、股权激励和重大资产交易公告。
- 返回结构化公告元数据，不直接产生投资判断。
- 依据公告日期和标题识别更正链，保留原公告与更正公告。
- 下载后校验 PDF 魔数、文件大小、哈希和可解析页数。
- 网络或官方接口失败时保留缓存并输出可诊断错误，不静默切换到低等级财务来源。

现有 `scripts/download_report.py` 改为下载执行器。正式披露来源优先；雪球和同花顺只能作为原件镜像降级，并在证据中明确标记，不再与巨潮资讯并列。

### 6.3 证据存储

新增 `scripts/evidence_store.py`，负责：

- 校验并序列化 `EvidenceRecord`。
- 生成稳定证据标识。
- 合并来自 PDF、公告元数据和行情的数据。
- 按裁决规则识别重复、冲突和无法比较的记录。
- 输出 `evidence_manifest.json` 和供人工查看的 `evidence_summary.md`。

### 6.4 财务标准化

新增 `scripts/financial_normalizer.py`，负责：

- 将金额标准化为百万元，同时保留原始数值和单位。
- 区分期间指标与时点指标。
- 处理季度累计值、单季度值、同比基期及追溯调整。
- 区分合并口径、母公司口径和分部口径。
- 对无法可靠换算或无法确定口径的值返回降级记录，不猜测。

现有 `scripts/pdf_preprocessor.py` 继续负责 PDF 文本与表格定位，不直接承担财务口径裁决。

### 6.5 财务质量指标

扩展 `scripts/quality_control.py`，在现有指标之外确定性计算：

- 净利润现金含量、自由现金流现金含量与多期稳定性。
- ROIC、投入资本口径和资本回报趋势。
- 应收账款、合同资产、存货和经营性现金流异常。
- 商誉、资本化支出、资产减值和非经常性损益影响。
- 有息负债、租赁负债、利息覆盖和短期偿债压力。
- 分红、回购、增发、股权激励和每股权益稀释。
- 会计利润与股东可分配现金之间的桥接。

每个指标引用输入证据标识，并在输入口径不完整时返回不可用状态，不输出伪精确数值。

### 6.6 行业适配

通用分析之外，首期增加三类适配器：

- 金融类：不机械套用工业企业 ROIC 和净债务指标，采用资本充足、资产质量和息差等适用指标。
- 周期与重资产类：突出周期中枢、维持性资本开支、产能和商品价格敏感性。
- 轻资产消费与服务类：突出单位经济、品牌或渠道、预收与营运资本、客户集中和获客效率。

无法匹配行业适配器时使用通用模板，并明确说明未应用行业专属模型。

## 7. Agent 分析流程

### 7.1 事实层

Agent 只能读取已验证证据和 Python 计算结果。事实陈述必须带来源标识，且不得重新计算 Python 已生成的指标。

### 7.2 商业判断层

六维商业分析的每项重要判断包含：

- 支持证据。
- 至少一项反证或替代解释。
- 置信度及其理由。
- 可能推翻当前判断的后续信息。

管理层评价必须区分经营能力、资本配置、信息披露和利益一致性。监管处罚、问询函、关联交易、股权质押和频繁融资属于必须检查项。

### 7.3 估值层

估值至少交叉使用：

- 穿透回报率。
- 历史估值区间。
- 对商业模式适用的 DCF、DDM、PE、PB 或 PS 方法。

输出悲观、基准和乐观情景，列示关键参数、适用条件和敏感性。不同方法差异较大时解释差异来源，不简单取平均。结论使用估值区间和安全边际，不给单一确定目标价。

### 7.4 时间纪律

- 每次分析记录知识截止日期和行情交易日。
- 历史回测不得使用当时尚未披露的数据。
- 年报、季报和公告按公开日期进入可用证据集。
- 滚动十二个月指标必须由可用期间数据确定性构造，并记录组成期间。

## 8. 报告与门禁

扩展 `scripts/report_consistency.py --gates`，加入以下硬门禁：

- 核心财务事实存在 S 级来源或明确降级说明。
- 所有估值输入可追溯到证据或 Python 计算结果。
- 报告期、交易日、币种、金额单位和合并口径没有未解释冲突。
- 重要判断包含反证和置信度。
- 悲观、基准、乐观情景齐全且参数范围一致。
- 数据截止日期与报告生成日期明确。
- 未解决冲突和缺失字段出现在最终报告的数据质量部分。

报告新增“数据质量仪表板”，展示：

- S/A/B/C 各级来源覆盖率。
- 官方来源覆盖的核心指标比例。
- 未解决冲突数量。
- 缺失或降级字段。
- 最旧和最新证据日期。
- 总体置信度及降级原因。

门禁失败时仍生成报告，但报告标题区必须显示低置信度警告，且不得输出高确信度仓位措辞。

## 9. 项目 Skills 调整

更新以下项目级 skills：

- `turtle-analysis`：先建立证据包，再运行定性、定量和估值流程；交付前执行全部门禁。
- `business-analysis`：强制检查反证、治理公告和证据覆盖率。
- `valuation`：只接受可追溯输入，强制输出情景和敏感性。
- `download-annual-report`：改为官方公告定位优先，并验证公告元数据与 PDF 原件。

新增 `evidence-audit` 项目 skill，允许独立检查一个分析目录的证据覆盖、来源等级、期间口径和估值输入可追溯性。该 skill 只编排确定性脚本，不自行生成或修改财务数值。

现有通用 skills 已覆盖需求拆解、TDD、系统调试、代码审查和交付验证。首期不安装来源不明的第三方金融 skill，避免将未经审计的方法引入分析链。

## 10. 错误与降级策略

- 官方站点不可用：使用已验证缓存；无缓存时标记缺失，不用财经门户财务摘要补值。
- PDF 为扫描件：尝试现有 PDF 降级解析；仍不可读时保留原件并要求人工或 OCR 补充。
- 指标冲突：保留候选证据并停止相关计算，直到按规则裁决。
- 行情缺失：允许使用 B/C 级降级行情，但估值报告标记交易日和来源等级。
- 行业模板不适用：退回通用分析并降低行业判断置信度。
- 单个维度失败：继续生成其余部分，最终报告明确列出未完成维度。

## 11. 测试策略

所有行为变化采用测试先行。测试完全离线，不访问外部网站。

新增固定样本覆盖：

- 官方来源与镜像来源的优先级。
- 年报更正覆盖原年报。
- 年报、季报和滚动期间错配。
- 元、万元、百万元和亿元的单位换算。
- 合并与母公司口径冲突。
- 追溯调整前后数据。
- 行情交易日与抓取日区别。
- PDF 校验、哈希和缓存降级。
- 证据冲突与 `unresolved` 状态。
- 门禁失败后的低置信度报告。
- 估值输入来源追溯和三情景完整性。

现有 267 项测试必须保持通过。新增模块需要单元测试；证据包到最终门禁至少增加一条离线端到端测试。

## 12. 实施边界与顺序

实施拆为四个可独立验证的阶段：

1. 来源注册表、证据模型和离线冲突裁决。
2. 官方公告定位、PDF 原件验证和证据 manifest。
3. 财务标准化、质量指标和行业适配。
4. Agent skills、报告仪表板、估值约束和最终门禁。

每个阶段先写失败测试，再实现最小功能，并在阶段结束时运行全量测试和独立代码审查。

## 13. 已知约束

- 免费官方站点可能限流、调整接口或要求浏览器行为，因此定位器必须可替换并支持缓存。
- 当前工作目录不存在 `.git`，无法创建隔离 worktree、提交规格或按阶段提交代码；实施前应优先恢复仓库元数据，或由用户明确接受在无版本历史目录中直接修改。
- 当前 Firecrawl skill 缺少可执行 CLI，首期设计不依赖 Firecrawl。
- 任何公开数据接口的具体端点都需在实施时以当前官方页面或公开协议验证，不在设计中固化未经验证的 URL。
